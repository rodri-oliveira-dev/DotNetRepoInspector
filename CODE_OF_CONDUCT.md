# Code of Conduct

**Languages:** English | [Português (Brasil)](CODE_OF_CONDUCT.pt-BR.md)

## Our commitment

DotNetRepoInspector should be a professional, welcoming place for technical collaboration. Contributors, maintainers, reviewers, and users are expected to treat one another with respect regardless of experience level, background, identity, location, employer, or point of view.

## Expected behavior

Examples of behavior that supports the project include:

- discussing ideas and code on their technical merits;
- giving specific, constructive feedback;
- asking clarifying questions without belittling others;
- acknowledging mistakes and correcting them;
- respecting reasonable boundaries, privacy, and confidential information;
- keeping disagreements focused on the work rather than the person;
- helping newcomers understand repository conventions when practical.

## Unacceptable behavior

The following behavior is not acceptable in project spaces:

- harassment, threats, intimidation, stalking, or targeted hostility;
- discriminatory, demeaning, or personally insulting comments;
- unwanted sexualized language or attention;
- publishing another person's private information without permission;
- deliberately disruptive behavior, spam, or sustained off-topic conflict;
- retaliation against someone who raises a good-faith conduct concern.

Technical disagreement is expected. Personal attacks are not.

## Scope

This code applies to issues, pull requests, discussions, reviews, repository-managed communication spaces, and other public interactions where someone is representing the project.

## Reporting and enforcement

If you experience or observe conduct that violates this policy, contact the maintainer privately using the contact methods available on the maintainer's GitHub profile. Do not post sensitive personal information in a public issue.

Reports will be reviewed as privately and promptly as practical. Depending on severity and context, maintainers may edit or remove content, request a behavior change, issue a warning, temporarily restrict participation, reject contributions, or permanently block participation in project spaces.

Good-faith reports will not be penalized. Knowingly false or malicious reports may themselves be treated as a conduct violation.

Security vulnerabilities are handled separately. Follow [SECURITY.md](SECURITY.md) rather than using a conduct report or public issue.

## Maintainer responsibility

Maintainers are responsible for applying this code consistently and proportionately. Enforcement decisions should focus on protecting healthy collaboration, not on winning technical disagreements.
